Digital Systems II, autumn 2025

Wi-Fi controlled smart lighting prototype

ESP32 firmware hosting a standalone Wi-Fi access point and an embedded HTTP server, serving a responsive web interface that controls four independent lighting channels in a scale model house.

ESP32C++Wi-Fi access pointHTTP serverREST endpointsJSONperfboard

The idea

The system had to work without any existing network, so the ESP32 hosts its own Wi-Fi access point rather than joining one. A phone or laptop connects directly to the board and opens a web interface served from the microcontroller itself, no cloud service, no router, no companion app.

Firmware and interface

An embedded HTTP server on the ESP32 serves a responsive page that adapts to a phone screen, with a control for each of the four lighting channels. Behind it sit REST-style endpoints: one set toggles a channel, another returns the current state of every channel as JSON, so the interface can reflect the real hardware state rather than assuming it.

Hardware

The circuit was assembled on perfboard with current-limiting resistors on each channel and a regulated 5 V supply, then installed in a scale model house so that each channel corresponds to the lighting in a different room.

What I took from it

Separating state from presentation turned out to be the useful lesson. Once the endpoints returned the actual device state rather than the last command sent, the interface stopped drifting out of sync with the hardware.
