Fault detection in a geared robot motor

A test rig that identifies the dynamic model of a geared DC motor from its own voltage, current and speed, then detects and tells apart common gearbox faults by how far the identified parameters move from the healthy baseline.

system identificationfault detectionDC motorprediction error methodPRBSrecursive least squaresMATLABencoder

The problem

In robots that run continuously the gearbox wears out before the motor does. The teeth abrade, the clearance between gears grows until the shaft turns freely for an instant on every reversal, and friction rises as lubricant dries. All three are gradual and invisible from the outside, so a motor is usually replaced only once it has failed outright and taken the robot down with it.

Each of those faults changes how the motor behaves dynamically. The same voltage reaches a different final speed, or takes a different time to get there. So the question is whether common gearbox faults can be detected, and told apart from one another, using nothing but the input voltage, the armature current and the shaft speed.

Approach

Neglecting the winding inductance reduces the voltage to speed behaviour of a small DC motor to a first order model with a static gain and a time constant, plus a constant term carrying dry friction. Those parameters are estimated from measured data by the prediction error method rather than derived from physical constants, which is what makes the comparison over time possible.

The rig is a geared motor on a fixed mount, its output shaft coupled to an auxiliary shaft carrying an adjustable friction brake and an inertia disc, so each fault can be induced in a controlled and reversible way. An H bridge sets the voltage under PWM, the encoder gives speed and a current sensor gives current. Sampling runs off a hardware timer near 1 kHz so the interval is uniform, because identification assumes a known sampling period and jitter turns into model error. The input is a pseudo random binary sequence, which spreads energy across a wide band, with steps and reversals alongside it.

Fault signatures

Because the parameters carry physical meaning, each fault should leave a distinct mark on them. That is what makes classification possible rather than just detection.

Detection comes from repeating the healthy experiment enough times to get a mean and a standard deviation per parameter, then flagging anything that lands more than three standard deviations out. The stretch goal moves estimation onto the microcontroller itself by recursive least squares, for a live reading of motor health while the robot works.

Status. Proposal stage. The rig, the identified model of the healthy motor and the fault signature table measured against real data will be published here as the work proceeds, along with the firmware and the analysis scripts.
